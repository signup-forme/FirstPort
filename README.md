# FirstPort

개인 프로필을 보여주고 GitHub 프로젝트를 소개하는 자기소개 웹사이트입니다.

## 🌐 배포 사이트

https://signup-forme.github.io/FirstPort/

## 🛠️ 포맷 별 역할

- HTML → 웹 페이지의 구조와 내용, 실행 결과를 보여주는 확장자
- CSS → 디자인과 레이아웃을 설계하는 확장자
- JavaScript → 백그라운드 동작을 실행하는 확장자

### 왜 따로따로 나눌까?

- 코드의 가독성을 높이고 유지보수를 용이하게 하기 위함이다.(만약 html용 코드, css용 코드, javascript용 코드가 한 파일 안에 뭉쳐있다면 매우 불편할 것이다. 이를 관심사의 분리 원칙이라고 한다.)
- css 파일과 javascript 파일은 브라우저의 캐싱 대싱이기 때문에 성능 향상에도 도움이 된다.

## ✨ 주요 기능

- 창 크기 축소 시 모바일용 레이아웃으로 변경(F12 개발자 모드를 사용하거나 창 자체의 크기를 조정)
- 모바일 햄버거 메뉴(三)

- 화면 모드 설정 내부 데이터에 저장 및 불러오기

- 최상단 이동 버튼

- GitHub API를 이용한 Repository 자동 불러오기 및 불러오기 실패 시 에러 처리[예) 계정명 틀림 / 호출 횟수 초과]

## 📱 반응형

다음 화면 크기를 기준으로 반응형 레이아웃을 구현했습니다. (아래 스크린샷 또는 실제 화면 상태 변화 참고)

- Mobile: 375px
- Tablet: 768px
- Desktop: 1024px / 1440px

### 모바일 퍼스트 반응형 디자인

- 모바일 기기는 컴퓨터에 비해 상대적으로 네트워크 속도와 처리 능력에 제약이 있어 기본 CSS를 모바일 레이아웃으로 가볍게 설계한 후 태블릿이나 데스크탑과 같은 대형 화면을 추가 확장하는 것이 리소스 관리 및 전달 측면에서 효율적이다.
- 작은 화면을 우선적으로 설계하여 페이지 내에서 중요도가 높은 기능과 콘텐츠에 집중하게끔 한다.
- 이외에도 과거와 달리 현대에는 스마트폰의 보급이 활발해져 스마트폰 이용자의 수가 높아진 것도 모바일 레이아웃 고려에 관여했다.

## 🔌 GitHub API

GitHub API를 사용하여 사용자 계정의 Repository를 불러옵니다.

API 요청 성공 시 사용자 계정에 업로드된 프로젝트들을 띄웁니다.

1. FirstWork → 코디세이 2기 입학연수 폴더
2. VibeCoding → 한양대 바이브코딩 프로그램
3. FirstPort → 이 프로젝트가 존재하는 폴더
4. Wait → 추후 선택 미션에 사용할 보너스 백업 폴더

## 💡 주요 JavaScript 구현

### Event → State → Render

다음과 같은 사용자 상호작용을 JavaScript로 구현했습니다.

- 햄버거 메뉴 → 메뉴 상태 변경 → 메뉴 렌더링
- 다크 모드 → 테마 상태 변경 → 화면 테마 변경
- 스크롤 → 스크롤 상태 변경 → 헤더 / Scroll Top 버튼 변경
- GitHub API → Loading / Success / Error 상태 → 프로젝트 목록 렌더링
- Contact Form → 입력 검증 상태 → 비어있거나 잘못 입력 시 오류 / 성공 메시지 렌더링

## Trivia

### 📄 상태(STATE) 객체가 있으면 좋은 이유?

- 산발적인 일반 변수로 두면 어떤 함수가 언제 값을 변경했는지 추적하기가 다소 까다롭고 이 과정에서 의도치 않은 에러가 발생할 수도 있다. 하나의 객체 안에 모아두면 데이터의 흐름을 파악하기 쉽다.
- 일반 변수는 화면 상태 동기화가 어려워지고, 상태가 변경될 때 어떤 화면 요소를 업데이트해야 하는지 매번 수동으로 관리해야 해서 그만큼 코드가 매우 복잡해지기도 한다. 그걸 방지하는 것이다.
